# Katana roadmap: a deterministic COBOL-to-Java migration compiler that proves itself

**Name: Katana** (Ghost, 2026-10-04: the tool that slices through one of the hardest problems in the
field; Japanese, and the street samurai's blade in the cyberpunk the Labs draw on). Repository:
`Ghost-in-the-Kernel-Labs/katana`.

**Status: proposed** (2026-10-04), written from the feasibility report
(`reports/COBOL to Java compiler feasibility.md`), the six research notes under `research_notes/`,
and the lessons of Suite Builder as recorded in its `theGhost.md`, `docs/GHOST-IN-THE-KERNEL.md` and
`docs/TRIM-REVIEW.md`. Where this document states a number, it was measured in this container on
2026-10-04 and the artifact that produced it is named. Where it states an estimate, it says so.

This is a plan, not a decision log. When a phase is built, its section shrinks to a ten-line header
naming the decisions it produced and what is left (Suite Builder lesson T-08), and the decisions
live in the project's own `theGhost.md`.

---

## 0. The product, in three sentences

Katana reads a COBOL batch program and its compile options and writes three things: Java that is
proven to produce byte-identical outputs to the original on the customer's own batch runs; a
provenance map tying every Java method and field to the COBOL paragraph, data item and PICTURE it
came from, and to the proof run that licensed its shape; and the equivalence harness itself,
which can verify anyone's Java, including IBM's. No model runs at conversion time. The literal
translation is kept as a pinned intermediate and never shipped; every refactoring beyond it is a
pass proven output-identical before it applies.

The thesis to hold: **JOBOL you can prove, refactored in steps each shown equivalent.** The thesis
to refuse, however often a buyer asks for it: "idiomatic Java," which no one can prove and which
Gartner's June 2026 forecast (more than 70% of 2026 mainframe exits failing) has made a liability.

## 1. What is settled: facts the roadmap stands on

Each is in the report with its source; the ids are for citation in decisions.

- **F-01** GnuCOBOL 3.1.2 installs from Ubuntu in about a minute and runs the NIST CCVS85 suite to
  `Total 426 426 0 0 9610 0 20 118 9748` in 96 s on two vCPUs, matching GnuCOBOL's shipped summary.
  Artifacts: `tools/nist/`, `tools/nist/summary.log`. Run with `-std=cobol85`; `-std=ibm` not yet run.
- **F-02** AWS CardDemo's POSTTRAN and TRANREPT batch jobs ran end to end against emulated VSAM and
  were byte-identical across runs only after `COB_CURRENT_DATE="2024-03-01 12:00:00.00 +00:00"` and
  `TZ=UTC` (hundredths of a second leaked into TRANFILE column 326). Indexed files differ in BDB page
  bytes between identical runs and must be compared on a key-ordered logical unload. Artifacts:
  `tools/runs/carddemo/`.
- **F-03** About 760 public programs are oracle-ready today: 400 NIST programs with reference
  reports (`eval-nist-cobol85`, Apache-2.0 over public domain), 359 GnuCOBOL autotests with
  byte-exact expected stdout, a handful of textbook programs. No realistic multi-thousand-line
  program ships expected output; every realistic oracle is generated by running the COBOL.
- **F-04** The redistributable corpus is CardDemo (Apache-2.0), NIST (public domain), GnuCOBOL
  autotests (GPL, test input only), ProLeap's feature programs (MIT). Rocket's BankDemo is
  internal-demonstration-only and stays private study. The CNAF programs (CeCILL-C) include one of
  213,838 lines. Corpus and `MANIFEST.md`: `corpus/`.
- **F-05** ProLeap's ANTLR grammars (MIT) parse 31/31 CardDemo, 79/82 BankDemo, 26/30 OMP course and
  279/459 NIST programs; of its NIST failures, zero are programs GnuCOBOL accepts. Koopa parses
  everything by silently dropping text (201,406 `<unknown>` nodes) and is disqualified. The only
  large open CICS and DB2 grammars are che4z's (EPL-2.0), generated here but not yet driven over the
  corpus. Results: `tools/results/`; drivers: `tools/proleap-cobol-parser/build/Driver.java`.
- **F-06** opensourcecobol4j's literal lowering (byte-image storage, decimal scratch registers, a
  label trampoline for PERFORM/GO TO, a provenance comment per statement) compiles and runs
  byte-identical to `cobc -x` on a construct test, with 4.2× line expansion. Its design is the
  specification for the literal intermediate; its GPL code stays out. Artifacts:
  `tools/runs/oc4j/CONSTR.{cbl,java,c}`.
- **F-07** The semantics the lowering must reproduce exactly are catalogued in
  `research_notes/.../semantic_traps.md`: store truncation by PICTURE, IBM intermediate precision
  (the dmax rule: `1 / 3 * 300` into `999V99` is 99.00 on IBM, 99.99 exact), TRUNC(STD/OPT/BIN),
  SIZE ERROR leaving the receiver unchanged, sign encodings by code page, REDEFINES and group MOVE
  as byte operations, OCCURS DEPENDING ON, PERFORM continuation semantics, byte collation, status
  codes instead of exceptions, WORKING-STORAGE persisting across CALLs.
- **F-08** Some behaviours cannot be made exact by construction and must be compile-time findings,
  never silent output: TRUNC(OPT), overlapping or recursive PERFORM ranges, division by zero without
  SIZE ERROR, ODO data beyond the count, COMP-1/COMP-2 hexadecimal float, reads of uninitialized
  storage.
- **F-09** No incumbent (IBM WCA4Z/Project Bob, AWS Transform, Google Dual Run, Heirloom, CloudFrame,
  TSRI, Mechanical Orchard, Hypercubic) publishes audited pass/fail numbers or emits provenance as a
  compiler artifact. IBM's own evaluation paper calls formal equivalence out of reach and dynamic
  testing the lowest-ROI check. Translation is given away by the hyperscalers; revenue is in
  assurance and partnership.
- **F-10** The IBM Enterprise COBOL 6.x manuals (intermediate results appendix, TRUNC, NUMPROC,
  SYNC, CICS translator output) returned HTTP 403 from this container. The numeric runtime cannot be
  frozen until they are read from an unblocked network.
- **F-11** The oracle harness alone is estimated at 7.5 to 9.5 engineer-weeks for a GnuCOBOL-only v1,
  the DFSORT subset the largest item. No source estimated the compiler itself; opensourcecobol4j's
  runtime is 87 source files and NACA's about 153,000 lines, which brackets the runtime.

## 2. Principles carried from Suite Builder

Each is a rule the project enforces by a test or a document from its first commit, not advice. The
Suite Builder evidence is in parentheses.

- **P-01 The oracle before the compiler.** Nothing in the lowering is written until a wrong answer
  can be caught by a run. (Suite Builder's bench arrived after grouping and had to refuse rules
  retroactively; here NIST hands over 9,610 tests on day zero.)
- **P-02 Byte-identical goldens are the only definition of done for a refactor.** A pass, a
  restructuring of the tool, a dependency change: each lands as its own commit with every golden
  unchanged, before the change that motivated it. (G-083.)
- **P-03 Findings before output.** A construct the lowering cannot make exact is reported first and
  lowered as a declared approximation second, never silently. (Suite Builder's site findings, G-132.)
- **P-04 One target until the shape layer is proven.** Java is the only back end until the Semantic
  IR and the dialect profile are stable on the whole corpus. No second language, no second JVM
  dialect. (The Cypress tree: a second generator copied instead of shared, TRIM-REVIEW T-04.)
- **P-05 Decisions numbered, with supersession checked by a test.** A decision that reverses another
  marks it superseded in the same commit, and a test fails when two in-force decisions contradict
  on a tracked subject. (G-025 sat in force beside G-124 for a day; here that is a wrong penny.)
- **P-06 Plans shrink into decisions.** A built plan becomes a ten-line header. (T-08.)
- **P-07 Nothing in the product that is not the product.** The customer receives the Java, the
  provenance map, the proof report and the harness fixture. Nothing of the tool's own personality
  ships. (The theme: 1,600 lines and a credibility cost in every Playwright suite, T-05.)
- **P-08 One canonical word per concept, from the first file.** The glossary exists before the second
  source file and a test holds the docs to it. ("Pages as crawled" had four names, T-21.)
- **P-09 The routing table is the front door.** `CLAUDE.md` is a table from task to the two to five
  files to open, their contract and their tests; nothing else is read first. (Suite Builder's best
  artifact.)
- **P-10 Ratchets only where there is debt.** An empty ratchet is ceremony an agent pays on every
  change. (T-07.)
- **P-11 Proven by a run, not on paper.** A pass that passes conformance but has not run on CardDemo
  is not done; the HANDOFF bar. Here it is structural, because the Java lane is the thing being sold.
- **P-12 Compiler options are semantics.** The dialect profile (compiler, version, TRUNC, ARITH,
  NUMPROC, code page, collating sequence) is a pinned input, written into the Semantic IR header,
  the Java manifest and every proof-ledger line. A proof is valid for one profile. (New here; Suite
  Builder had no analogue, and the APAR PH64935 case shows IBM itself changed intermediate rounding
  between releases.)
- **P-13 The maintainer is Ghost; nothing proprietary enters the repository.** Customer programs,
  customer data and anything under a license that forbids redistribution never enter git. (G-007,
  G-085.)
- **P-14 The agent's environment is a first-class deliverable, funded at a fixed share of effort.**
  Ghost's observation from Suite Builder: delivery speed rose measurably once the agent's ability to
  find, read and change code with little context was treated as work worth doing. About a tenth of
  Suite Builder's effort went there. This project is larger and has a second language in the tree,
  so the share rises; section 5 sets it at **one commit in eight, and one full pass per phase**, with
  metrics that ratchet. This is not hygiene; it is the lever on the quality of everything else.

## 3. Architecture

### 3.1 The pipeline, as a compiler

```
COBOL + copybooks + JCL + dialect profile
        │
        ▼
  [front end]  ANTLR (ProLeap grammars, forked; che4z CICS/DB2 sub-grammars)
        │   → parse tree, preprocessor-resolved (COPY, REPLACE), source map to file:line
        ▼
  [Semantic IR]  exact, complete, mechanically derived: data map (every item's offset, length,
        │        attribute tuple), paragraph graph with PERFORM continuations, every statement
        │        as an operation over Fields, file descriptors, the dialect profile header
        ▼
  [literal lowering]  Java that is a byte-image machine: byte[] per 01-level, Field views,
        │             Decimal scratch with the profile's arithmetic rules, for(;;) switch(pc)
        │             dispatcher with a PERFORM continuation table, status-returning I/O.
        │             One provenance comment per statement. PINNED: the golden for all that follows.
        ▼
  [oracle]  run original under GnuCOBOL (or a customer's mainframe output), run the Java,
        │   compare logical record streams field by field under the copybooks. Twice each.
        ▼
  [Intent IR]  inferred facts with evidence, confidence and confirmation state: this item is
        │      money; these 88-levels are an enum; this PERFORM range is a function; this
        │      REDEFINES is a tagged union; this paragraph set is reducible.
        ▼
  [passes]  each a function (Semantic IR, Intent IR, literal Java) → Java, applied only where
        │   its proof obligations are discharged, each proven on the oracle before it applies
        ▼
  [proof ledger]  append-only: pass P, licensed by intent fact F, proven by oracle run R,
        │         changed Java method M, which stands on COBOL paragraph Q. The provenance map.
        ▼
  shipped: refactored Java + manifest + provenance map + proof report + harness fixture
```

### 3.2 The three IRs, and why there are three

**Semantic IR** is what the program does. It is derived from the parse tree and the dialect profile
with no judgment anywhere, and it is complete: everything the literal lowering emits comes from it
and nothing else. Its contract is a document held to the code by a test (Suite Builder's
`SUITE-IR.md` and `suite-ir-doc.test.ts`), with numbered invariants (SIR-01 ...). It has one
reader that matters, the literal lowering, and one check that matters, the oracle.

**Intent IR** is what the program means. Every fact in it is inferred by a named rule from evidence
in the Semantic IR (the PICTURE, the 88-level values, the paragraph graph, how an item is referenced
across the program), carries a confidence, and carries a confirmation state: inferred, confirmed by a
person, or refuted. No pass may act on a refuted fact; a pass acting on an unconfirmed fact says so
in the ledger. The Intent IR is the "intent directive" of the original idea. It is also the only
place a model could ever be allowed near this product, and then only to *propose* facts a person
confirms, never at conversion time (a decision to record as refused for v1, so the question stops
being asked).

**Proof ledger** is what was done and why it was allowed. It is append-only: a mapping is never
edited, only superseded by a later line that cites it. Every Java method and field in the output
has at least one line. It is the kernel map of Suite Builder pointed at the customer's program
instead of the tool's own code, and it exists for the same reason: the thing that stops a later
change from destroying evidence of an earlier one. Determinism comes from the Semantic IR; the
ledger adds nothing to it. Provenance comes from the ledger; the IR adds nothing to that. They are
kept apart so neither is bent to do the other's job.

**Dialect profile** is the fourth structure and the smallest: compiler and version, TRUNC, ARITH,
NUMPROC, code page, program collating sequence, the per-flag mapping to GnuCOBOL's dialect
configuration (`arithmetic-osvs`, `perform-osvs`, `move-ibm`, `hostsign`, `odoslide`,
`binary-size`, `binary-truncate`, `sticky-linkage`). It is content-addressed; its hash appears in
the Semantic IR header, the Java manifest, every oracle fixture and every ledger line.

**Findings** are the fifth: what the input program does that the tool cannot make exact (F-08), and
what the input program does that is wrong by its own lights (dead paragraphs, unreachable ALTER
targets, uninitialized reads). Said first, in the build's output, before any Java.

### 3.3 Module layout

One module per concern (the count lives in `docs/modules.json`); each has an entry in `docs/modules.json` stating purpose,
inputs, outputs, what it may import, what it must not, and its entry points, and a test holds the
imports to it (Suite Builder's `modules.test.ts`). The import lists in `modules.json` are the law;
the order below is prose, not a layering rule (`passes/` imports `ledger/`, which is listed after it).

```
katana/
  front/        parsing and preprocessing → parse tree + source map. Imports: nothing of ours.
  profile/      the dialect profile: schema, GnuCOBOL flag mapping, hashing.
  sir/          the Semantic IR: types, build (tree → IR), check (invariants), contract (facts).
  lower/        literal lowering: Semantic IR → Java source. Decides nothing.
  rt/           the Java runtime the literal Java links against: Field, Record, Decimal,
                ArithProfile, Dispatcher, files, SORT, CALL. Pure Java, no dependency.
  oracle/       job fixture model, the two runners (cobc lane, java lane), the comparator,
                the determinism gate, DD binding, the DFSORT subset, stubs (LE, assembler).
  intent/       the Intent IR: fact types, inference rules (each named, each with evidence),
                confirmation state, the human review file format.
  passes/       refactoring passes: each a file, each with its obligations, its proof, its
                ledger lines. Imports sir, intent, ledger; never oracle (the driver runs the oracle).
  ledger/       the proof ledger: append-only store, line schema, the provenance map writer,
                the report writer.
  findings/     what is wrong with the input, what cannot be exact.
  cli/          turns what was typed into a workflow in project/ and prints what it did.
  project/      the workflows on disk: build, prove, pass, report, pack, fixture.
  bench/        the corpus runner: NIST, autotests, CardDemo; scores recorded and held by a test.
```

Rules the layout implies, each a test from phase 0: `lower/` reads `sir/` only and builds no
decision (Suite Builder's SRC-10); `passes/` never writes Java directly, only through the same
emitter `lower/` uses, so provenance comments cannot be lost; `rt/` has no dependency and no
reference to the tool (it ships); `oracle/` never imports `lower/` or `passes/` (the referee does
not read the players' code); nothing in `front/` knows what COBOL means.

### 3.4 Language and toolchain (decision for Ghost, with a recommendation)

**Decided (Ghost, 2026-10-04; R-001): Java 21 for everything** — compiler, runtime, harness, CLI —
built with Gradle, dependencies vendored into the repository or served from a pinned mirror.

Why: the runtime must be Java, so Java is in the tree regardless; ANTLR's home target is Java and
the forked grammars need no bridge; the comparator and harness ship to Java shops as one jar; a
single toolchain means a single test runner, a single lint, a single set of rule tests; and the
buyer's reviewer reads one language. Against: Suite Builder's meta-tooling (knip, biome, vitest,
the kernel scan) is TypeScript and would be rewritten; Ghost's own fluency is C#/C++ and the
Selenium-era Java. The alternative, TypeScript compiler with a Java runtime, keeps Suite Builder's
tooling but splits every rule test across two languages and makes the harness two artifacts.

Environment consequence either way: this container's proxy blocked Maven Central, Gradle
distributions and GitHub release assets (F-05's build notes). The project vendors its few
dependencies (ANTLR runtime, JUnit, a JSON library) under `third_party/` with licenses, or runs its
own mirror, so an agent can build offline from a clean clone. Record as a decision (R-001) with the
environment note; it is also the first item of the agent-environment work in section 4.4.

### 3.5 What is deliberately not built

A COBOL parser from scratch; CICS screen (BMS) emulation beyond what parsing needs; any step that
calls a model during conversion; a second target language (the C++ idea is dropped: it is a port,
not a translation, and no mainframe buyer asks for it); JCL beyond the subset CardDemo and the
first customer use; online (CICS transaction) equivalence in v1. Each is a recorded decision so the
question is answered once.

## 4. Meta-architecture: what holds the project together for a person and an agent

Everything here exists before the first line of `sir/`. It costs about three days and is the cheapest
work in the plan per unit of later pain avoided.

### 4.1 The documents, and which test holds each

| Document | Holds | Held by |
| --- | --- | --- |
| `CLAUDE.md` | the routing table: task → files, contract, tests; the commands; the two rules | `docs.test`: every path it names exists (SRC-15) |
| `theGhost.md` | every decision R-001..., with Decision / Why / Held by / Source / Status / See also | `ghost.test`: ids unique and sequential; a superseded decision names its successor and the successor names it; two in-force decisions tagged with the same subject do not conflict (a `conflicts-with:` line is a failure) |
| `docs/decisions.md` | one line per decision, 20 words max, written by a script | `ghost.test` compares |
| `docs/GLOSSARY.md` | one canonical term per concept, aliases listed; an alias in backticks is enforced, the rest are a review guide (R-039) | `glossary.test`: an enforced alias appearing in a doc outside the glossary and `docs/research/` fails |
| `docs/SEMANTIC-IR.md` | the Semantic IR contract, invariants SIR-nn | `sir-doc.test`: every exported type and invariant in the doc, and the reverse |
| `docs/PROFILE.md` | the dialect profile fields and their GnuCOBOL mapping | `profile.test` |
| `docs/PROOF.md` | what a proof is, what it covers, what it never covers | `report.test`: the shipped proof report quotes it verbatim |
| `docs/modules.json` → `MODULES.md` | per-module purpose, imports allowed and refused | `modules.test` |
| `docs/KERNEL-MAP.md` | the tool's own function ledger, append-only | `kernel-map.test`: a function removed or renamed without a `superseded-by` line fails |
| `TODO.md` | open items only, in order; done items in `docs/DONE.md` with their numbers kept | `todo.test`: headings in numeric order; every "first open item" has a check |
| `docs/HANDOFF.md` | what is waiting on a run, what is waiting on whom; nothing else | by review |
| `docs/AGENT.md` | the agent-environment contract (section 4.4) and the tithe metrics | `metrics.test` ratchets |

The register (T-21 lesson): decisions keep the Decision / Why / Held by shape, which is good for a
machine; every rule in every document opens with a bold imperative clause and an id; metaphors are
allowed only after the rule has been stated plainly.

### 4.2 The rule tests on the tool's own source

From Suite Builder's SRC rules, kept only where they caught something there:

- Layering per `modules.json` (SRC-05/08/10 equivalents): the one rule that caught the most.
- `lower/` and `passes/` build no locator, decide nothing: every branch on a COBOL property is in
  `sir/` or `intent/`.
- Function size and path count as *warnings* listed by `metrics`, not failures (G-107's lesson); a
  function over the limit has a comment saying what it is for.
- A function that holds a decision cites it, `// Decision: R-021`, and the cited decision exists.
- Dead code refused (a knip equivalent for Java: unused public symbols fail the build).
- `// Unsure:` lines listed, never failing.
- Ratchets (`DEBT`) created only when a rule arrives with existing violations, deleted when they
  reach zero.

### 4.3 The kernel map for the tool

`docs/KERNEL-MAP.md` is generated from the source by a script and committed; its diff is reviewed.
Each function: module, name, the decision it stands on or the caller it serves, first seen. A line is
never edited; a function that goes away gets `superseded-by:` or `removed:` with the commit. This is
the guardrail that tripped in Suite Builder before logging existed, and the project is larger.

### 4.4 The agent's environment

A contract in `docs/AGENT.md`, each line a measurable:

- **Clean clone builds offline.** `./gradlew build` with no network, from `third_party/`.
- **The fast loop is under 20 s.** `npm test`-equivalent: unit tests only, no cobc, no javac of
  generated suites. Integration (`cobc` lane, NIST, CardDemo) is a separate target with its own
  budget (NIST full: under 3 minutes; CardDemo: under 1 minute).
- **Mandatory context is under 1,500 words.** `CLAUDE.md` plus whatever an agent must read before a
  task. Measured by the metrics script.
- **A task's row opens at most five files, none over 400 lines.** Measured per row.
- **Generated files are marked and excluded from diff review.** `.gitattributes`
  `linguist-generated -diff` for bundles, maps, the kernel map's body.
- **Every generated artifact has a command that regenerates it and a test that fails when stale.**
- **The container image is pinned** (GnuCOBOL 3.1.2 or 3.2 by digest, JDK 21, Gradle, the corpus
  mounted). An agent never installs tooling.
- **Rendered views are committed where the source is indirect.** If templates or slots are ever
  used, the rendered Java is committed under `docs/rendered/` (T-20).
- **Logs are structured and short.** The oracle's first-difference report fits on one screen.

### 4.5 The agent as a reader of the proof

One design consequence of P-14 that is also product: the proof report, the provenance map and the
findings are written so that an AI agent working inside the customer's migrated Java can read them
as facts with evidence. "This method stands on paragraph 2000-COMPUTE-INTEREST, licensed by intent
fact I-0412 (enum from 88-levels, confirmed by J. Smith 2027-03-02), proven by run R-00891 on
profile 3f9a..." is a line both a maintainer and an agent can act on. Suite Builder's `ai/` folder
in generated suites is the precedent; here it is the product's reason to exist.

### 4.6 How a question is answered, and when the work stops (R-052, R-053)

A question met during the work is classed, not escalated by reflex:

| Class | Who answers | What the agent does meanwhile |
| --- | --- | --- |
| an implementation choice inside a contract | the implementing agent | decides, journals, continues |
| a factual claim with an empirical referee | a **trial**: a fixture, test or measurement whose result is the answer | specifies it (or asks Fable to), runs it, decides on the result |
| a contract, IR shape, semantic rule, reading of a source | Fable, at the phase boundary | lists it under HANDOFF "For Fable", takes the reversible default marked `// Unsure: R-053 default`, continues |
| scope, license, name, money, a new module, anything outside parties see, anything irreversible | Ghost, at the phase boundary | lists it under "For Ghost"; continues on a reversible default if one exists, else stops that step and works on what is independent |

Fable is a source of answers and of trial designs, consulted when the agent is uncertain; it is not
a second opinion to argue with, and a trial runs only when the consulted answer is itself uncertain.
A phase runs from its first step to its last on this rule; the boundary is where the deferred lists
are answered, defaults reversed under goldens, and the count of held-versus-reversed defaults
recorded by the tithe.

## 5. The navigation tithe

**Cadence.** Every eighth commit is a tithe commit: it changes no behaviour (goldens identical) and
improves the agent's environment or the code's navigability. Every phase ends with a tithe pass of
one to two days. Phase 0 is itself mostly tithe.

**What a tithe commit may do.** Split a file over 400 lines along a seam named in `modules.json`;
rename for the glossary; move a decision comment to where the decision is actually made; shrink a
built plan to its header; add a `See also` line to a decision; collapse a duplicated helper; cut a
slow unit test to the integration target; update a stale `CLAUDE.md` row; vendor a dependency that
was reaching for the network; add a regeneration command for something hand-maintained; write the
missing top-of-file purpose paragraph; delete an empty ratchet.

**What a tithe pass does** (end of phase): re-measure every metric below and record it in
`docs/AGENT.md`; read `CLAUDE.md` as a new agent would and time how long it takes to find the file a
representative task needs; run the "fresh agent" trial from Suite Builder (a copy of the repo, an
agent told only the task, phrased as a proposal — "say what you would change, then stop" — scored on
whether it opened the right files first and changed nothing); fix what the trial showed.

**Metrics, ratcheted** (may improve, never regress without a decision):

| Metric | Phase 0 target | Why it matters to the agent |
| --- | --- | --- |
| Mandatory context (words) | < 1,500 | every task pays it |
| Fast loop (s) | < 20 | the agent runs it after every edit |
| Largest source file (lines) | < 400 | fits a read without paging |
| Files a routing row opens | ≤ 5 | first five reads decide the task |
| Functions over 20 paths | 0 new | branching is where agents misread |
| Duplicate helpers (same body, two names) | 0 | the agent edits one and misses the other |
| Decisions without `See also` | 0 | grep misses what links find (T-18) |
| Docs lines per source line | < 0.35 | Suite Builder reached 0.37 and it hurt |
| Stale generated artifacts | 0 | detected by test |
| Skipped tests reported on the fast loop | 0 | a real skip hides among 119 (T-15) |

**Share.** One in eight commits plus a pass per phase is roughly 15–18% of effort, above Suite
Builder's tenth, by design: two languages in the tree, a runtime that ships, and a corpus that must
be mounted mean the environment has more ways to rot.

## 6. Phases

Each phase has steps; each step has a check that fails before the work and passes after; each phase
names the decisions it records and ends with a tithe pass. Durations are estimates for one engineer

### Phase 3: literal lowering and the runtime, proven on NIST (about eight weeks)

The literal Java is the golden. It is a byte-image machine (F-06, F-07), and this phase is where

    division by zero as a status; sign codecs by code page and `hostsign`; MOVE rules (elementary

### Phase 6: proven refactoring passes (about eight weeks, open-ended by design)

Each pass is a file in `passes/`, with: its name; the intent facts it requires; its obligations as
checkable properties on the Semantic IR and the dispatcher graph; the transformation; the proof
(the oracle run on every golden, byte-identical, plus the paragraph-entry trace equal); and the
ledger lines it writes. A pass that cannot discharge its obligations on a program does not apply to
it and reports why. Order by provability:

6.1 **Pattern structuring**: `GO TO` to the next paragraph becomes fall-through; a PERFORM range
    satisfying `Function` becomes a method; `PERFORM VARYING` with a provably monotone counter
    becomes a `for`. (Ceccato et al.: patterns alone removed 21% of GOTOs on 8 MLOC; this is the
    cheap, safe first fifth.)
6.2 **Method extraction under the dispatcher**: a reducible paragraph set becomes a method with
    local control flow; the dispatcher shrinks; the residual `switch` stays for what is not reducible,
    with a finding naming it. (Böhm–Jacopini removed 79%; Erosa–Hendren's 100% at +232% nesting is
    refused as a decision.)
6.3 **Scalar promotion**: an item with no REDEFINES, RENAMES, reference modification, ODO, group
    MOVE or raw I/O touching it, and `NeverOverflows` proven (interval analysis plus the corpus
    never setting SIZE ERROR), becomes a typed field (`long` with scale, or `BigDecimal` with an
    explicit scale and the profile's rounding mode).
6.4 **Exact-arithmetic substitution**: step-wise IBM arithmetic becomes exact arithmetic only where
    no division or non-integer exponent can trigger dmax truncation.
6.5 **Enum and flag types** from `Enum`/`Flag` facts; **money** as a dedicated type from `Money`.
6.6 **Stateless subprograms** where every WORKING-STORAGE item is written before read on every path.
6.7 **Record classes** from 01-levels with no aliasing, keeping the byte codec at the I/O boundary.
6.8 **Refactoring distance, per pass and cumulative**, in the proof report: lines, nesting,
    dispatcher cases remaining, scalars promoted, obligations not discharged and why.
    *Check for every pass:* all phase-3 and phase-4 goldens byte-identical; paragraph-entry trace
    equal; the ledger has a line per changed symbol; the pass's own unit corpus (the GnuCOBOL
    autotests that exercise its construct) passes.
6.9 **Tithe pass 6.**

Decisions recorded: R-032 passes apply only where obligations are discharged, never with a warning;
R-033 the Erosa–Hendren total structuring refused; R-034 the residual dispatcher is acceptable
output and is reported; R-035 the refactoring-distance report.

## 7. Risks, in the order they would kill the project

- **R-A GnuCOBOL stands in for IBM.** Default division computes 38 extra places where IBM holds
  dmax; `-std=ibm` is a best-effort encoding; hexadecimal float, NUMPROC detail and TRUNC(OPT) have
  no exact analogue. Mitigation: profile as a pinned input (P-12); the manuals read before `rt/`
  is frozen (F-10); phase 9.5; the report's wording.
- **R-B CICS, DB2 and JCL are where every open tool stops** and DFSORT is open-ended. Mitigation:
  batch only (R-005); facades with recording stubs; JCL built on demand from real jobs.
- **R-C Licensing and disclosure.** EPL-2.0 grammars inside the compiler (R-015); GPL code of `cobc`
  and `cobj` never copied, only their outputs used as oracles; CeCILL-C and BankDemo never
  redistributed; and any public disclosure before the provisional is filed forfeits patent rights
  outside the US and starts the US clock (R-037).
- **R-D The market gives translation away.** Revenue is assurance and partnership; the harness is
  sellable at the end of phase 1 and that is the first sale to attempt.
- **R-E Project Bob ships a verification story first.** GA planned 2026; the window for "the
  independent oracle" is this year. Phase 1's deliverable is the answer; nothing in phases 2–6 is
  needed to make it.
- **R-F The compiler's effort is the team's own estimate.** Phases 2–6 total about 28 weeks here
  with no published comparable (F-11). Mitigation: every phase has a sellable or publishable
  artifact, so a slip is a delay, not a loss.
- **R-G Agent-environment rot.** Two languages, a runtime that ships, a mounted corpus, a pinned
  compiler. Mitigation: section 5, funded and ratcheted.
- **R-H The proof is mistaken for a guarantee.** The NYT, TSB and Phoenix cases are not code
  semantics. Mitigation: `PROOF.md`'s not-covered list in every report (R-013), and no sales
  language that omits it.

## 9. Glossary seed (one word per thing, from the first file)

- **Program**: one COBOL compilation unit. **Job**: a JCL job of steps. **Step**: one program run
  with its DDs.
- **Profile**: the dialect profile (3.2). Never "options", "flags", "settings".
- **Semantic IR**: what the program does. **Intent IR**: what it means. **Ledger**: what was done
  and why it was allowed. **Map**: the provenance map written from the ledger.
- **Literal**: the pinned Java the lowering emits. Never "JOBOL" (a market word, used only when
  quoting), "intermediate", "golden" (reserved: see next) or "lowered Java".
- **Golden**: a recorded expected output a test holds the code to (NIST reports, CardDemo hashes).
- **Fixture**: a content-addressed job description with its inputs, environment and stubs.
- **Lane**: one runner over a fixture: the cobc lane, the java lane, the Hercules lane.
- **Oracle**: the comparison of two lanes' outputs under the copybooks. **Gate**: the double-run
  determinism check before any oracle.
- **Finding**: what is wrong with the input or cannot be exact; said first.
- **Pass**: one refactoring, with its obligations and its proof. **Obligation**: a property a pass
  must discharge before applying. **Distance**: how far a pass moved the Java from the literal.
- **Fact**: one line of the Intent IR, with evidence, confidence and state.
- **Tithe**: a commit or pass that changes no behaviour and improves the agent's environment.
- **Ghost**: the maintainer. **Reviewer A, B...**: outside reviewers by letter.
